## Chapter 26: Domain playbook: enterprise

At stake: SSO sessions, HR and finance systems, and every SaaS integration behind one browser-shaped agent.

One multi-tool agent with standing SaaS access is many single-purpose sandboxes waiting to be split. Catalog rehearsal: *Attacker impersonates the agent to other systems*; *Supervisor agent rubber-stamps compromised workers*; *Hierarchical agents delegate until the bill exceeds the project budget*; *Secrets exfiltrated through telemetry and debug logs*; *Agent's long-term memory planted with a standing instruction*; *Poisoned document in the vector store steers decisions for months*; *Self-parallelizing agent spawns an unbounded fleet of sub-agent copies*; *Multi-tenant agent leaks one customer's data to another* (8 of the domain's scenarios).

Catalog weight behind this chapter: 13 patterns, 8 scenarios, 20 cascades (inherent 11, emergent 0, derived 8, cascading 1).

**Definition 1 (Integration-per-sandbox).** The enterprise deployment satisfies *integration-per-sandbox* iff (i) each SaaS integration is served by exactly one sandbox holding exactly that integration's provider-bound credential, (ii) no standing cross-integration session exists, and (iii) every integration is a named, reviewed edge with session expiry on a cadence.

**Theorem 1 (Blast stops at the integration).** Under integration-per-sandbox with identity-first controls, compromise of one sandbox exposes at most one integration for at most one session lifetime — impersonation, rubber-stamping, delegation blowout, telemetry exfil, planted memory, poisoned vectors, fleet spawn, and tenant leakage are each bounded by the sandbox wall.

*Proof.* Single-purpose sandboxes partition the eight shapes by construction: impersonation steals one integration's session (expired on cadence, SSO-gated); rubber-stamping is confined to the workers in one sandbox; delegation blowout is capped by per-sandbox fan-out plus the bill alarm; telemetry exfil reads one sandbox's logs; planted memory and poisoned vectors persist in one sandbox's context (flushed at generation retirement); fleet spawn from one sandbox hits the cap and the halt; tenant leakage crosses no boundary because tenants never share a sandbox. Approval on admin actions plus prover checks on scope changes keep the edges reviewed. Split one multi-tool agent this week; inventory every SaaS scope; rehearse the SSO-abuse story first — the primitives say so, in that order. ∎
