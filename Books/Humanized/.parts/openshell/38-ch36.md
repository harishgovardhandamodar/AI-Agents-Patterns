## Chapter 36: Domain playbook: operations

At stake: Runbooks, incident actions, status pages, and the production systems behind them.

The agent sent to fix the incident must not be able to deepen it; mutation waits for the commander. Catalog rehearsal: *Self-healing agent restarts the wrong fleet during an incident* (1 of the domain's scenarios).

Catalog weight behind this chapter: 3 patterns, 1 scenarios, 2 cascades (inherent 1, emergent 0, derived 1, cascading 0).

**Definition 1 (Commander-gated mutation).** Operations satisfies *commander gating* iff (i) agents run read-only diagnostics freely (runbooks read, incidents read, notes write-only), (ii) every mutation — fleet restart, status change, production action — waits for the incident commander's explicit approval, (iii) credentials are per-incident and expire with it, and (iv) timelines are append-only with automatic evidence capture.

**Theorem 1 (Healers cannot harm).** Under commander gating, a self-healing agent — however misdiagnosed the incident — can investigate freely but cannot mutate: the wrong-fleet restart waits at the commander's approval, which sees the full (possibly wrong) diagnosis before authorizing anything.

*Proof.* Diagnostics are reads (i): the agent may gather, correlate, and propose without bound. Mutations are commander acts (ii): the restart executes only on explicit approval, and the commander sees the diagnosis (possibly wrong) plus the evidence (timeline, notes) before deciding. Per-incident credentials (iii) bound even approved actions to the incident. The runbook as written is the goal comparator's objective: runbook-deviation rehearsal tests whether the agent follows the written procedure, and deviations are flagged before they execute. Gate one production runbook action; verify agents cannot mutate production outside commander approval; confirm incident timelines append-only. The healer that would restart the wrong fleet instead files a wrong proposal — reviewed, rejected, recorded. ∎
