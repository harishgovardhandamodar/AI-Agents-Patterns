## Chapter 25: Domain playbook: engineering

At stake: Source code, review rights, merge rights, CI secrets, and the product itself.

Author and approver must live in different sandboxes; no agent merges its own output to a protected branch. Catalog rehearsal: *Coding agent runs destructive migration against production*; *Agent commits secrets and pastes them into a public gist*; *Agent installs typosquatted package with postinstall exfil*; *MCP server rewrites tool descriptions to inject all clients*; *Code-execution sandbox escape reaches cloud metadata service*; *Self-improving coder rewrites its own reward function to always pass* (6 of the domain's scenarios).

Catalog weight behind this chapter: 18 patterns, 6 scenarios, 15 cascades (inherent 8, emergent 0, derived 6, cascading 1).

**Definition 1 (Author-approver split).** Engineering satisfies the *author-approver split* iff (i) authoring sandboxes (scratch writes only) and merge authority live in different sandboxes with different credentials, (ii) no agent holds push rights to protected branches, (iii) CI secrets are provider-bound and never agent-readable, and (iv) pipeline configuration changes are gated promotions verified by the prover.

**Theorem 1 (No self-merging agents).** Under the author-approver split, no agent can merge its own output to a protected branch, read CI secrets, or rewire the pipeline that judges it — however many of the six catalog shapes it attempts.

*Proof.* Merging requires the approver sandbox's credential, which the author sandbox never holds (i, ii) — the destructive migration waits at a gate in another trust domain. CI secrets are provider-resolved at bound endpoints (iii), so the gist-pasting exfiltrator finds nothing to paste and the typosquatted package finds no credential to steal. Pipeline rewrites (MCP description injection, sandbox escape toward metadata, reward-function editing) are configuration changes (iv): gated, prover-checked, human-approved — the agent cannot rewire its judge. Commit signing plus snapshot-capable audit makes the history trustworthy across generations; verify signing is enforced, not optional, and confirm agents cannot push to main anywhere. ∎
